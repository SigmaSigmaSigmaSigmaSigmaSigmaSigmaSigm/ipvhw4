1. HTTP — протокол обміну запитами та відповідями між клієнтом і сервером. HTTPS — HTTP через захищене TLS-з'єднання.
2. Типовий порт HTTP — 80, HTTPS — 443.
3. HTTP-повідомлення бувають запитами клієнта та відповідями сервера.
4. Для HTTP/1.1 повідомлення складається зі стартового рядка, заголовків, порожнього рядка і необов'язкового тіла. У запиті стартовий рядок містить метод, адресу ресурсу та версію; у відповіді — версію, код стану й опис.
5. GET отримує ресурс, POST надсилає дані для обробки або створення ресурсу, PUT замінює ресурс, PATCH частково змінює, DELETE видаляє. HEAD отримує заголовки без тіла відповіді, OPTIONS — доступні можливості. CONNECT створює тунель, TRACE повертає діагностичне відображення запиту.
6. 1xx — інформаційні відповіді, 2xx — успіх, 3xx — перенаправлення, 4xx — помилка клієнта, 5xx — помилка сервера. Приклади: 200 OK, 201 Created, 204 No Content, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 500 Internal Server Error.
7. Cookie — невеликі дані, які браузер зберігає для сайту і надсилає у відповідних HTTP-запитах. Використовуються для сесій та налаштувань. Сервер може встановити їх через Set-Cookie.
8. AJAX — асинхронний обмін даними з сервером без повного перезавантаження сторінки. Можна використовувати fetch або XMLHttpRequest, формат даних часто JSON.
9. AJAX дозволяє оновлювати потрібну частину сторінки: наприклад, завантажити ще 10 викладачів, залишивши інший вміст на місці.
10. JSON — текстовий формат обміну даними: об'єкти, масиви, рядки, числа, true, false, null. JSON.parse перетворює JSON-рядок на значення, JSON.stringify — значення на JSON-рядок.
11. CORS — механізм, яким сервер через HTTP-заголовки дозволяє браузеру читати відповіді з іншого origin. Origin складається зі схеми, хоста і порту. Для деяких запитів браузер спочатку надсилає OPTIONS preflight. mode: no-cors не дає прочитати відповідь JavaScript-кодом.
12. Promise представляє результат асинхронної операції: pending, fulfilled або rejected. then обробляє успіх, catch — помилку, finally виконується після завершення. Promise.all очікує всі результати і відхиляється при першій помилці; allSettled повертає результати всіх операцій; race — перший завершений результат; any — перший успішний. async/await — зручний синтаксис роботи з Promise. fetch не відхиляє Promise лише через статус 404 або 500, тому перевіряємо response.ok.
